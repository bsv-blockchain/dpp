# dpp-epcis-lifecycle@1 vectors

`v1.json` pins the EPCIS lifecycle claim (`spec/epcis-lifecycle-claim.md`): one EPCIS 2.0.1 event in a signed envelope over its RFC 8785 bytes. The file is generated by `packages/dpp-credentials/test/epcis-lifecycle-vectors.ts` and held identical to its generator by `packages/dpp-credentials/test/epcis-lifecycle.test.ts`; change the generator and run that suite with `REGENERATE_FIXTURES=1` to move it, and review the diff.

Six parties sign, each the `did:key` of an identity key whose scalar is published under `keys`; a seventh is the anchoring service and an eighth is a second anchoring service. Every identifier is synthetic: GS1 keys under the demonstration prefix 952, hosts under example.org. Nothing derived from the scalars will ever hold value. Each vector's `options` are data, read as the file's `notes` say, and every positive event is held to the pinned EPCIS 2.0.1 JSON schema, which each reader obtains from GS1.

| Vectors | What they prove |
|---|---|
| `object-event-commissioning` to `recycling-4-end-of-life` | All five event types and the representative cases: creation, manufacturing as a transformation without action, shipping, receiving, packing, unpacking, assembly, repair, a reversible component association, inspection with a linked result, a business-transaction association, separate ownership and possession, a sensor observation, possession without ownership, a sale that asserts no ownership and a four-step recycling chain with an extension business step under a required rule |
| `recycling-3-shredding-rule-unavailable`, `without-caller-evidence`, `extension-term-without-rule` | What the verifier was not given stays unavailable or unknown, never passed, and an extension term the claim lists no rule for is unavailable whatever the verifier holds |
| `binding-to-another-passport` to `lot-in-epc-list-as-item` | Incorrect product binding, and class-level references that never stand in for an item |
| `altered-secured-bytes` to `altered-profile-digest` | Altered bytes, non-canonical bytes, and altered context and profile digest bindings |
| `event-id-not-expected` to `local-identity-as-event-id` | A wrong or missing eventID, and a digest or local identity presented as the event's identifier |
| `valid-signature-unsupported-authority` to `authority-scope-without-binding` | A valid signature without authority, an importer signing as observer, contradictory party roles and a scope without a binding |
| `duplicate-and-conflicting-observations` to `no-declaration-in-a-complete-set` | The same claim, a conflict, a restatement and another issuer's attestation; an error declaration, its effect, one by an issuer without authority and one by a claim that is not itself sound |
| `anchor-about-unbound-subject` to `anchor-mismatch-on-another-bound-passport` | Anchors another service wrote under the claim's identifier: one about a passport the claim does not bind is set aside, and a mismatch on one that names a bound passport fails that passport and no other |
| `refused-*` | Claims never issued: events built from a sale, a metadata edit or a token transfer alone, a transformation with an action, an aggregation without its parent, an event type outside the five, and an importer as observer |
