# GS1 discovery vectors

Vectors for the `gs1-digital-link@1` discovery profile (`spec/gs1-discovery.md`), in the BSV stack's conformance vector format like every file under `fixtures/vectors/`. They are generated by `packages/dpp-profiles/test/gs1-resolution.test.ts` and held identical to what that test produces; `REGENERATE_FIXTURES=1` rewrites them, and the diff is the review. Every host is an `example.org` or `example.com` name, every GTIN is under the demonstration prefix 952 or is the one GS1 itself uses in its worked example, and nothing here names a deployment.

| File | What it pins |
|---|---|
| `uri-syntax.json` | The uncompressed grammar for primary key 01: a URI with every qualifier and data attributes read apart, a bare GTIN, a GTIN-8 under a stem, a failing check digit reported and not refused, the three spellings of `linkType`, the compressed form detected, and ten refusals each with its reason (`unsupported-primary-key`, `no-primary-key`, `qualifier-order`, `qualifier-repeated`, `qualifier-unsupported`, `qualifier-value`, `key-in-query`, `attribute-value`, `trailing-segment`, `percent-encoding`). |
| `epc-binary.json` | Decompression of the special compressed form: the compression standard's two published worked examples (`eh` hexadecimal and `ex` URI-safe base 64, one SGTIN-96, decoded to `/01/09528765123457/21/123456789123`), a stem and query carried across, an SGTIN-198 built by this package's own encoder (a layout vector, not an independent one), and four refusals (uncompressed input, another EPC scheme with its header named, upper-case hexadecimal, wrong length). |
| `resolution.json` | Resolution over one set of five demonstration records (`records` in the file): the hierarchy of GS1-Conformant Resolver 1.2.1 §2.5.10 for serialised, variant-and-lot and lot-only requests, a default inherited from the model level and labelled model information, a lot nobody registered walking up to the GTIN-level default (§2.5.9) and the same request answered with no record over the item record alone, a requested type found and not found, language and media-type refinement, the fallback to the single default, an undeclared-language link outranking mismatches, a genuine tie answered as multiple choices, a restricted link absent for a public audience and flagged for an authorised one, an unknown GTIN, the linkset document for the serialised request (which validates against the pinned GS1 linkset schema), the resolver description file (which validates against the pinned description schema), and the record set rule with each of its refusal reasons: the five records admitted together; the item record alone, the four qualified records without the GTIN-level record, and those four with a GTIN-level record whose only defaults are refined ones, each refused because their GTIN has no single default at the GTIN level; those four with a restricted GTIN-level default; and the five with a second GTIN-level record carrying another single default. A vector that carries `recordIndexes` runs over only the records of the file's `records` it names by position, followed by any records it carries in `addedRecords`; every other vector runs over all five. The event repository link is registered under `gs1:epcisRepository`, which GS1 Web Vocabulary 1.18 names as the replacement of the deprecated `gs1:epcis`. |

The independent expected results are GS1's own: the two worked examples of the compression standard. Everything else states what the reference implementation produces so that a second implementation can be held to the same bytes; a vector's `description` says which kind it is.
