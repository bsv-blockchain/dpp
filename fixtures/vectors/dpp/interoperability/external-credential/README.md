# External credential vectors: `vc-di-ecdsa-rdfc-2019@1`

`v1.json` pins independently constructed cases for the external credential profile (`spec/external-credential-profile.md`) in the BSV stack's cross-language vector format: identifier `dpp.interoperability.external-credential.v1`, twenty vectors, each with the exact credential string, the pinned documents a verifier needs (issuer DID documents, public keys, the status list credential), the verifier policy, the SHA-256 of the exact bytes, and the expected outcome and first issue code of every check together with the reason codes the verification report carries. Every host is an example host (`issuer.example`, `other.example`, `id.example.org`), the demonstration GTIN sits under GS1's prefix 952, and no vector describes a real product or a real issuer.

The keys are published. The positive vector's `keys` carries each key's identifier, controller, curve and its public and secret Multikey encodings; the secrets are one byte repeated to the curve's scalar length (`0x11`, `0x22`, `0x33` for the P-256 keys and `0x44` for the P-384 key), so a reader in any language rebuilds the same key pairs from the description alone. Nothing derived from these keys will ever hold value. The ECDSA proof values are not reproducible from the keys, because the suite signs with a random nonce; a reader verifies the pinned proofs rather than recomputing them.

| Vector | Proves |
| --- | --- |
| `positive` | Every check verifies: pinned contexts, owned schema, P-256 `ecdsa-rdfc-2019` proof under a key the `did:web` document lists for assertion, expected subject, validity, authenticated fresh status list, trusted issuer, everything available. |
| `reformatted` | The same credential pretty printed: the RDF proof holds, the exact-byte digest differs (C-11). |
| `tampered-subject` | One subject value changed in the bytes: the proof fails. |
| `context-substituted` | An inline context object appended: contexts and proof unsupported, never trusted. |
| `key-substituted` | Signed by a key the issuer holds but never authorised: binding and proof fail. |
| `issuer-substituted` | Issuer names another party while the key belongs to the first: controller mismatch, proof fails, status list issuer mismatch, authority unconfirmed. |
| `expired`, `not-yet-valid` | The validity interval excludes the evaluation time, each named. |
| `revoked` | The status list bit is set under a fresh, authenticated list. |
| `status-other-issuer` | A list from a party the policy never delegated to. |
| `status-list-unavailable` | No pinned list and no fetch: status and availability indeterminate. |
| `p384-key` | An authorised P-384 key the suite could verify: unsupported, not failed, not verified. |
| `jcs-suite` | `ecdsa-jcs-2019` declared: unsupported before any signature evaluation. |
| `two-subjects` | Validly signed with two subjects: proof holds, schema and subject binding refuse. |
| `subject-bound-by-policy` | The signed subject is an alias related to the passport only by a named binding policy with an evidence reference. |
| `subject-mismatch` | The same alias with no binding policy: mismatch, nothing inferred. |
| `authority-not-required`, `issuer-untrusted` | The two authority policies, never read from the credential. |
| `status-missing-optional` | No status entry under the option that accepts it, with the limitation recorded. |
| `id-collision` | Two valid credentials under one identifier with different bytes, for a registry's intake refusal. |

The file is generated by `packages/vsc/test/exchange-fixture.ts` through `packages/vsc/test/exchange-vectors.test.ts` with `REGENERATE_FIXTURES=1`; without that variable the test verifies the pinned file, so a verifier change that alters an outcome goes red without a signature being regenerated. `examples/verify-external-credential.mjs` reads the positive and tampered vectors from the packed package.
