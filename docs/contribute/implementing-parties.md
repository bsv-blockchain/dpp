# Implementing parties

The [governance source](https://github.com/bsv-blockchain/dpp/blob/8691c12c6e81f54216ec30fe4c688f5d1b82b644/GOVERNANCE.md) defines participation and the evidence needed for independent implementation. Participation alone does not establish a tested implementation.

## Prepare to participate

Choose the roles and profile versions the implementation will cover. Build a fixture harness, retain the implementation's authorship and dependencies, and produce per-case results before arranging an exchange.

The first useful contribution is a reproducible difference: an input both implementations read, the results they produced and the rule behind each reading. A fresh-record exchange comes after the individual components can explain their own results.

Use [the trial guide](../implement/demonstration.md) to prepare endpoint addresses, policies and retained evidence with another participant. Participation, code independence and separately administered operation are different facts; record which have actually been demonstrated.

Start with the [implementation route](../implement/README.md), then retain [authorship and test evidence](../implement/reporting.md). The [trial definition](https://github.com/bsv-blockchain/dpp/blob/8691c12c6e81f54216ec30fe4c688f5d1b82b644/conformance/demonstrations/independent-implementation-2026-09.json) identifies the proposed exchange work.

The [ledger](https://github.com/bsv-blockchain/dpp/blob/8691c12c6e81f54216ec30fe4c688f5d1b82b644/conformance/manifest.json) keeps the independent-implementation gate open. Use the [contact route](disagreements.md) to submit results or arrange participation.
