# Technical reference

Implementers and reviewers can use this index to locate exact rules, interfaces, supported entry points and implementation evidence. If you are still choosing what to build, start with [your platform brief](../start/plan-your-platform.md) or [build or integrate](../start/build-and-integrate.md).

- Required input: your selected release or source revision, from [release sets](release-sets.md) or your checkout; keep its versions and evidence together.

| Find | Start here |
|---|---|
| The protocol rules and profile definitions | [Specification index](specifications.md) |
| HTTP interfaces, schemas and other contracts | [Contracts and schemas](contracts.md) |
| Reference packages and supported APIs | [Install the selected release](../packages/README.md) and [supported entry points](../packages/support-table.md) |
| Requirements for another implementation | [Independent implementation](../implement/README.md), including role guides and fixtures |
| Publication and conformance evidence | [Release sets](release-sets.md) and [conformance ledger](conformance.md) |
| How to propose a change or report a disagreement | [Contribution process](../contribute/README.md) and [disagreements](../contribute/disagreements.md) |

Published packages, the latest source and a hosted deployment can differ. If a specification, contract, fixture or implementation disagrees, retain the conflicting artefacts and report them through the documented disagreement process. Do not silently invent a new rule.
